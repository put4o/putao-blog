# agent的四层可调用信息

 coding agent的四种上下文来源
 * **当前事实**：当前代码、git、配置、任务状态等需要实时读取的内容
 * **会话记录**：历史会话（原文+摘要）
 * **长期记忆层**：Memories（cc中叫auto Memories）索引文件自动注入上下文
 * **持久指令**：长久稳定，且每个会话都需要遵守的规定；自动注入上下文；agent.md/claude.me

修改代码即修改**当前事实**
当前上下文的最终会被组织到下一轮的**会话记录**
对话中经验类的会被提取到**长期记忆层**
指令类的需要用户指定后添加到**持久指令**
新窗口自动加载**长期记忆**和**持久指令**

# 阶段一：从旧会话提取候选记忆

codex默认不启用；启用后，十天之内、六小时之前的旧会话会被自动整理。

整理方式：从旧会话中提取三类内容进行长期存储
* raw_memory: 详细经验描述
* rollout_summary: 更简短的摘要
* rollout_slug：标签

在会话中寻找几类内容：
* 长期稳定的用户偏好：工作习惯、交付要求
* 验证过的高价值方法
* 稳定的环境与工作量：工作流、工具链等
# 阶段二：整理为记忆文件

从第一阶段提取的记忆中，根据使用频率和实践进行排序，筛选出符合整理条件的记忆；

启用一个专门的agent（不联网、无法启用新的sub agent）进行整理：
* 整理Memories_summary.md(记忆系统的索引，每次都会被注入上下文)
* memory.md(写清楚每个项目的边界范围，防止项目之间污染)
* 原始材料
* 会话摘要和证据
# 阶段三：新会话召回

1. memory_summy.md每次都会自动注入新会话；
2. 会话中如果存在内容可能和记忆有关时，会在memory_summy.md中进行检索，返回索引后
3. 根据索引进入Memories.md中进行检索
4. 加载相关记忆内容。
5. 被加载的文件使用次数+1（为了进行长期记忆的淘汰，不常用的要进行淘汰）

# codex对比cc

| 对比维度   | claude code   | Codex             |
| ------ | ------------- | ----------------- |
| 记忆开关   | 默认开启          | 默认关闭              |
| 记忆存储范围 | 按 Git 项目分仓库存储 | 全局统一一套            |
| 写入时机   | 即时写入          | 延迟整理              |
| 存储方式   | 纯 Markdown 文件 | 数据库 + Markdown 混合 |
| 淘汰机制   | 无自动淘汰         | 根据时间和使用次数自动淘汰     |
